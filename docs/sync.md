# iCloud 사용량 동기화

## 작성권과 데이터 경로

`UsageSyncEngine` actor가 디스크 접근을 담당한다. 서버 응답과 기존 `UsageHistoryPersistence`의 로컬 저장을 먼저 UI에 반영하고, 별도 작업으로 로그 집계·동기화를 수행한다. 갱신이 겹치면 진행 중인 작업 하나와 최신 대기 요청 하나만 유지한다. 샘플 모드, 계정 변경, 설정 해제, 종료는 세대 번호와 취소 검사로 이전 결과의 화면 적용을 차단한다.

각 `(계정, 기기, UTC 날짜)` 파일에는 작성자가 하나다. 동기화 결과는 화면용이며 기존 로컬 원본 저장소나 자신의 송신 파일에 다시 저장하지 않는다. 이 규칙이 복제 증폭과 양방향 합산 오류를 방지한다. 로컬 `flock`은 같은 설치의 중복 프로세스 쓰기를 막고, `NSFileCoordinator`와 atomic replace는 macOS 파일 동기화 작업과의 충돌을 조정한다. 취소 핸들러는 대기 중인 파일 조정도 취소한다.

로컬 보관함을 먼저 갱신한 뒤 공유 폴더에 게시한다. 재시작하면 자신의 보관함을 복원하고 공유 파일의 실제 내용을 비교해 미전송 상태만 재시도한다. iCloud 전달 완료를 자체적으로 판정하지 않으며, 표시하는 기기 시각은 해당 기기가 마지막으로 기록한 시각이다.

## 집계

토큰 이벤트는 기존 추정기의 내용 없는 SHA-256 식별값을 base64로 보관한다. 같은 이벤트가 복사된 로그나 여러 기기에 있으면 증가분의 최댓값을 한 번만 사용한다. 계정·경로 추정의 한계는 README와 같다. 토큰은 구독 사용 비율로 환산하지 않는다.

한도는 원본 관측을 먼저 병합한다. 동일 시각은 한도 종류별로 최신 리셋과 낮은 잔여율을 선택하며, 같은 리셋 기간에는 잔여율의 하한을 유지해 지연 응답이 같은 감소분을 다시 발생시키지 않게 한다. 이 방식은 서버가 같은 기간의 사용량을 정정해 잔여율을 올린 경우 이후 일부 사용량을 보수적으로 적게 잡을 수 있다. 실시간 잔여 게이지는 계속 서버 값을 사용한다.

과거 요약과 상세 관측의 겹침은 시간 경계 sweep으로 해결한다. 상세 관측이 우선하고, 요약끼리는 관측 비중, 사용률 순서로 결정한다. 각 시간 조각에 하나의 출처만 적용하므로 양쪽 앱의 실행 시간이 겹쳐도 관측 시간과 사용량이 두 배가 되지 않는다. 상세 관측이 요약의 일부 구간만 보완하면, 그 상세 사용량을 요약 총량에서 차감한 나머지를 미관측 부분에 배분해 기존 합계가 잘려 나가지 않게 한다. 15분 요약 내부의 실제 관측 위치는 이미 소실됐으므로 그 구간은 추정이다. 집계는 Mac의 현지 날짜를 사용하고 전송 파일은 UTC 날짜로 나누어 시간대 차이와 DST에 따른 파일 충돌을 피한다.

## I/O 제한

- 현재 UTC 날짜 + 이전 9일, 기기 폴더 최대 64개만 조회한다.
- 파일 하나는 최대 16 MiB, 하루 관측 3,000개·토큰 이벤트 100,000개로 검증한다.
- 메타데이터가 그대로면 내용 읽기 0회. 저장 내용이 같으면 인코딩·쓰기 0회.
- 현재 날짜의 관측 시각과 스캔 시각은 최소 1분 간격으로 갱신한다. 정상 5분 주기에는 관측 공백 판별을 위해 현재 파일을 갱신한다.
- 과거 파일은 늦게 발견한 토큰이나 최초 이전 자료가 있을 때만 바뀐다.
- 만료 정리는 하루 한 번, 자신의 파일만 수행한다. 다른 기기 자료는 읽기만 한다.
- 파일 내려받기 재요청은 5분 간격. 변경 없는 손상 파일은 재파싱하지 않는다.
- peer 파일 캐시는 메모리에만 두며 iCloud 로컬 사본을 다시 별도 디스크 캐시로 복제하지 않는다.

## 검증과 한계

`make test`가 독립된 두 로컬 보관함과 임시 공유 폴더를 사용한다. 실제 계정이나 iCloud 파일을 테스트 데이터로 덮어쓰지 않는다. 동시 쓰기, 토큰 중복, 지연 한도 응답, 동일 파일 재조회, 재시작, 현재 파일만 갱신, 과거 파일 불변, 오프라인 재전송, 계정 분리, 손상 파일 복구, 과거 요약의 겹침, 만료 정리, 전날 로그 꼬리, 지연된 과거 버전, 취소, 숨겨진 화면에서의 수집, 설정 해제와 샘플 격리를 검증한다.

확인된 I/O: 변경 없는 반복 교환은 파일 내용 읽기 0회·로컬 쓰기 0회·공유 쓰기 0회다. peer 파일 하나가 변경되면 읽기 1회만 발생한다. 디렉터리 목록 및 메타데이터 조회는 포함하지 않은 수치다. 별도의 네트워크 사용량이나 SSD 물리 쓰기량 감소율을 의미하지 않는다.

두 실제 Mac 사이의 iCloud 전송 지연·오프라인 재접속은 해당 두 장비에서 추가 확인이 필요하다. 테스트는 iCloud 파일의 전달 순서와 장애를 로컬 파일로 재현한다. 일별 한도는 관측으로부터 계산한 추정값이며, 관측되지 않은 과거 구간을 생성하지 않는다.
